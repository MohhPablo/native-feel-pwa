# Improved execution prompt

Build and deliver `native-feel-pwa`, a general-purpose MIT-licensed Agent Skills repository for Build, Audit, Fix and Optimize workflows in existing or new PWAs. Optimize for reuse, correctness, focused diffs and verifiable evidence, not code volume or claims of flawless/native-equivalent output.

First read the current Agent Skills specification and authoritative browser/framework documentation. Keep a dated source ledger linking each capability claim to primary evidence. Review overlapping skills and component ecosystems. Distinguish normative requirements, documented browser support, observed heuristics and product preferences. Refresh package maintenance/license/compatibility at selection time; never infer these from popularity.

Design a concise SKILL.md with correct frontmatter and progressive disclosure. Require repository inspection and a dated reuse decision BEFORE implementing components. Compare local components, browser primitives and credible open-source candidates using hard accessibility/license/framework gates, ownership cost and measured bundle impact. Do not automatically install or migrate; follow existing authorization and preserve the host architecture.

Cover accessible touch/keyboard/zoom/focus/scroll/motion, iOS and Android differences, manifests/install, online-first and offline-capable policies, private data, worker updates, multiple tabs, recovery and unsupported-feature fallbacks. Preserve selection and zoom by default. Explain the practical iOS 16px input heuristic without presenting it as a guaranteed standard. Never trade accessibility for superficial native feel.

Implement read-only cross-platform Node validation tools with documented scope, actionable exit codes, bounded traversal, no symlink escape or secret disclosure, and tests for malformed input and false positives. Include real examples, lockfiles, optional runtime accessibility/mobile tests, CI, MIT license, contribution/issue templates, compatibility instructions, changelog and roadmap. No private application code.

Follow stages: research → architecture → implementation → tools/tests → exercised examples → self-audit/release. Do not stop at a plan. Run actual tests and builds; classify every acceptance check PASS, FAIL or NOT RUN with commands and environment. A static scan is not runtime proof; emulated WebKit is not iPhone validation; lab budgets are not field Core Web Vitals. State unresolved physical-device work explicitly.

Deliver the repository, architecture, installation and mode examples, pre-implementation reuse evidence, before/after audit demonstration, test log and known limitations. Never invent success, publish externally without authorization, or alter unrelated files. If blocked, complete all feasible work and report the exact remaining limitation.
